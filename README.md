# ObsFit

Минималистичный Android-дневник питания для локального хранилища Obsidian. Записи и справочник хранятся в Markdown; Syncthing переносит их между устройствами. Нативный Java-интерфейс, Android 13+, целевой Android 16, package `ru.obsfit`.

## Сборка и установка

Нужны JDK 21, Android SDK 36.1 и Build Tools 36.1.0. Задайте SDK через `ANDROID_HOME` или `sdk.dir=/путь/к/Android/Sdk` в локальном `local.properties`.

```sh
./gradlew :core:test :app:lintDebug
# Только по отдельному запросу сборки APK:
./gradlew :app:assembleDebug
python3 tools/check-apk-alignment.py app/build/outputs/apk/debug/app-debug.apk
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Локальная готовая копия текущей версии: `dist/ObsFit-0.4.5-debug.apk`. APK, `dist/`, ключи подписи, SDK-настройки и каталоги сборки исключены из Git.

Передайте APK на телефон и установите. При запросе разрешите установку из используемого файлового менеджера. Локальные обновления подписываются тем же debug-ключом; удаление приложения для обновления не требуется. Debug-ключ не публикуется в репозитории.

При первом запуске выберите **Внутренняя память → Documents → obs → YaDiskVera → Использовать эту папку**. Нужен корень хранилища, содержащий `Еда.md`, `Замены.md` и `Дневник/Хроника`. До выдачи доступа дневник недоступен. Разрешение на папку сохраняется; после перемещения папки или отзыва разрешения выберите её заново.

## Работа с дневником

Основной экран и сканер закреплены в вертикальной ориентации. Поворот телефона не пересоздаёт экран приложения.

Верхняя панель: **≡** — справочник, **↻** — обновление, **⚙** — настройки. Стрелки переключают только существующие ежедневные заметки; пропущенные даты перескакиваются, недоступные стрелки бледные. Нажатие на дату открывает список уже загруженных дней. Если сегодняшней заметки нет, выбирается ближайшая прошедшая. Создавайте новые ежедневные заметки в Obsidian.

На экране дня приложение слушает уведомления системного файлового провайдера и раз в 12 секунд проверяет дату изменения и размер `Еда.md`, `Замены.md` и открытой заметки. Метаданные сравниваются с кешем последней успешной загрузки. При совпадении содержимое файлов не читается, экран не перерисовывается. Уведомления объединяются с задержкой 600 мс; при изменениях данные обновляются без индикатора загрузки, с сохранением прокрутки и раскрытых разделов. Во время редактирования форм фоновые обновления экрана приостановлены.

При возвращении в приложение файлы перечитываются в фоне независимо от метаданных. Если провайдер не сообщает дату или размер, используется чтение файлов с проверкой содержимого. Ошибка фонового чтения не заменяет данные на экране; следующая проверка повторяет попытку. При запуске и выборе хранилища полоска загрузки показывается на всё время подключения и поиска дней. Ручной **↻** принудительно читает файлы открытого дня, обновляет ближайшую порцию дат и показывает полоску загрузки. В справочнике **↻** принудительно перечитывает справочник. Новые дни обнаруживаются при ручном обновлении или подключении хранилища.

При старте загружается только список ближайших дат: до семи заметок до выбранной и семи после неё. Содержимое читается только у выбранного дня. Полного обхода хроники нет: приложение использует границы папок года, квартала, месяца и ISO-недели, пропуская вложения. Дойдя до двух дней от края загруженного списка, приложение фоново добавляет ещё семь дат с этой стороны, сохраняя предыдущие. Внутри загруженной порции новые запросы списка не выполняются. Папки с нестандартными названиями поддерживаются, но для поиска ближайшей даты их приходится проверять без отсечения по времени.

Норма берётся из `СуточнаяНормаКалорий::` в разделе «Спорт и диета» открытого дня. При отсутствии корректного положительного числа используется **2150 ккал**. До последних 100 ккал перед нормой цвет зелёный, последние 100 ккал до нормы включительно — жёлтый, выше нормы — красный.

Разделы: Заметки, Завтрак, Перекус 1, Обед, Перекус 2, Второй обед, Перекус 3, Ужин, Перекус 4. Каждый сворачивается, показывает калории и содержит компактную **＋** в заголовке. Добавление доступно и в свёрнутом разделе.

- На экране добавления еды рядом находятся **＋ Новая еда** и **＋ ккал**. При вводе новой еды или калорий левая кнопка становится **Из справочника** для возврата к списку. Кнопка **＋ ккал** переключает на ввод калорий прямо на этом экране: необязательное описание и итоговое число, без веса и всплывающего окна. В этом режиме сверху находятся **Из справочника** и **＋ Новая еда**. «Добавить» сохраняет строку `описание 350 ккал` или `350 ккал` только в выбранный раздел дня, без изменения справочника и списка недавно выбранных продуктов. Эти калории входят в итог раздела и `СъеденоКалорий::`; запись можно редактировать, переносить и удалять как обычную порцию.
- Нажатие на порцию — редактирование порции.
- Свайп вправо — сразу выбор раздела для переноса.
- Свайп влево — сразу подтверждение удаления. До подтверждения файл не меняется.
- Меню ⋮ предоставляет те же действия.
- В форме порции **✎** рядом с названием открывает отдельный редактор продукта в справочнике. После сохранения или возврата восстанавливаются введённый вес и актуальные данные продукта.

Известные порции распознаются по полному названию и алиасам: `бт`, `бт 60`, `бт 60 г`, `белый хлеб 60 г 120 ккал`. Название без веса использует порцию по умолчанию. Неизвестные строки `150 ккал` или `другая еда 150 ккал` учитываются как есть; просто `150` не считается калориями. Код, цитаты, таблицы, комментарии, зачёркнутые строки и Dataview-поля исключены. Еда из прочих разделов отображается в «Заметках».

Приложение читает рассчитанную норму из дневника, формулу похудения само не пересчитывает и ключ нормы не переписывает.

При открытии дня калории известных порций вычисляются по актуальному справочнику **для отображения**. Файл дня и `СъеденоКалорий::` обновляются при сохранении изменений дня либо при форматировании в Obsidian. Массового переписывания исторических заметок после изменения справочника нет.

## Подсказка по приёмам пищи

Под дневными калориями сегодняшней заметки показан приблизительный остаток текущего приёма и следующий приём. В промежутках и при исчерпанном бюджете текущего приёма показывается обратный отсчёт. Подсказка помечена `≈`: времени у записей нет. На других датах она скрыта. После 22:00 или при достижении нормы открытого дня следующий приём по расписанию — завтрак завтра в 09:00; недобор и перебор на завтра не переносятся.

| Время | Приём | Базовые ккал |
| --- | --- | ---: |
| 09:00–10:00 | Завтрак | 500 |
| 11:00–12:00 | Перекус 1 | 225 |
| 13:00–14:00 | Обед | 400 |
| 15:00–16:00 | Перекус 2 | 225 |
| 17:00–18:00 | Второй обед | 400 |
| 18:00–19:00 | Перекус 3 | 225 |
| 19:00–20:00 | Ужин | 400 |
| 21:00–22:00 | Перекус 4 | 225 |

Таблица задаёт базовые пропорции на 2600 ккал. Для нормы открытого дня все порции пропорционально масштабируются; временные окна сохраняются; размер основных приёмов и перекусов — выбранные предпочтения. Точные часы, частота и пропорции не выдаются за универсальную диетическую норму. Общие рекомендации — устойчивый подход к питанию, соответствующая потребностям суммарная калорийность и разнообразные продукты: [NIDDK](https://www.niddk.nih.gov/health-information/weight-management/adult-overweight-obesity/eating-physical-activity), [NHS](https://www.nhs.uk/live-well/eat-well/how-to-eat-a-balanced-diet/eight-tips-for-healthy-eating/). Подсказка — бюджет плана; она не требует доедать остаток или запрещать еду вне расписания.

Все восемь приёмов сопоставляются со своими разделами дневника, поэтому перекусы больше не распределяются приблизительно по времени. Если в старой заметке есть только `### Перекусы`, приложение показывает её содержимое в «Перекус 4» и пишет добавления туда же, сохраняя старый заголовок. При наличии обоих заголовков их строки учитываются один раз в четвёртом перекусе, а добавления идут в явный «Перекус 4». Разделы 1–3 при добавлении создаются между соответствующими основными приёмами; пустые секции и старые файлы при открытии не переписываются. Старые сохранённые формы и состояние раскрытия раздела тоже преобразуются к имени «Перекус 4».

«Заметки» по-прежнему учитываются приблизительно: относятся к текущему приёму, а в промежутке — к последнему прошедшему. Чтобы отнести такую еду к определённому приёму, перенесите запись в его раздел. Каждый ккал входит в расчёт один раз; время записей не сохраняется.

Недобор и перебор завершённых приёмов поровну прибавляются к оставшимся или вычитаются из них. Съеденное в текущем и будущих разделах вычитается из их бюджета. Если получается отрицательное значение, оно обнуляется, а лишние калории поровну вычитаются из остальных доступных приёмов. После округления сумма доступных бюджетов совпадает с целым остатком дневного ориентира. Например, завтрак 350 вместо 500 добавляет примерно по 21–22 ккал каждому из семи оставшихся приёмов; завтрак 650 убирает примерно столько же. Пропущенные приёмы тоже дают перенос; поэтому скорректированный перекус может стать больше базовых 225 ккал.

Отсчёт показывает часы и минуты с округлением вверх и обновляется на границе минуты только при открытом приложении, без файлового I/O и перерисовки экрана целиком. Изменения записей, веса и справочника берутся из актуального снимка дня. Новых полей или скрытых комментариев в Markdown нет.

## Справочник и составные блюда

**≡ → ＋ Новая запись** создаёт продукт без добавления порции в дневник. «Новая еда» в форме порции создаёт и продукт, и порцию. Нажатие на продукт в справочнике редактирует название, алиасы, калорийность и вес. Свайп открывает подтверждение удаления. Продукт, используемый в составе блюда, удалить нельзя, пока его не уберут из состава. Полные записи порций в дневнике не удаляются вместе с продуктом.

Продукт попадает в результаты, если буквы запроса встречаются в названии или одном отдельном алиасе в том же порядке, с произвольными пропусками. Например, `рст` и `ркм` находят «растворимый кофе с молоком». Длина названия относительно запроса не ограничивает такие совпадения. Буквы из разных алиасов не объединяются; повторяющиеся буквы должны встречаться нужное число раз.

Поиск по названию и алиасам учитывает опечатки, перестановки соседних букв, пропуски букв и части слов в любом порядке. Примеры: `колбса`, `паулниа`, `овс бл`. Регистр, `е`/`ё` и разделители не важны. Точные совпадения показываются первыми; при одинаковой точности учитывается недавность добавления порций. Эта статистика хранится только на телефоне.

Секция **«Ингредиенты»** доступна как в редакторе справочника, так и в режиме **«＋ Новая еда»** при добавлении порции. Для новой еды состав сохраняется в `Еда.md`, а порция с фактическим весом и калориями — в выбранный раздел дневника. Вес по умолчанию и ккал/100 г вычисляются автоматически и недоступны для ручной правки, пока есть ингредиенты. Вес порции изначально следует весу блюда; после ручного изменения сохраняет введённое значение при правках состава.

Состав находится в раскрывающейся секции **«Ингредиенты»**. Выберите продукты или блюда через поиск и задайте их вес. Нажатие на вес меняет граммы; × убирает ингредиент. Повторное добавление продукта суммирует вес. Готовое блюдо сохраняется одним ингредиентом: половина бутерброда весом 60 г добавит «бутерброд 30 г». Вложенные рецепты поддерживаются; калорийность рассчитывается по всей цепочке состава. Циклические рецепты запрещены. Вес блюда и ккал/100 г рассчитываются автоматически.

При переименовании прежнее полное название сохраняется как алиас для дневниковых записей. Ссылки в ингредиентах переводятся на новое название, в том числе при удалении прежнего алиаса. Совпадения с другим продуктом или `Замены.md` блокируют сохранение.

В `Еда.md` используется одна таблица между маркерами:

```markdown
<!-- food-table:start -->

| Название и алиасы | Ингредиенты | Ккал на 100 г | Вес по умолчанию, г |
| --- | --- | --- | --- |
| белый хлеб<br>бт | | 200 | 40 |
| сыр | | 300 | 20 |
| бутерброд | белый хлеб 40 г<br>сыр 20 г | 233.33 | 60 |

<!-- food-table:end -->
```

Алиасы и ингредиенты разделяются `<br>`. Вес положительный; нулевые калории допустимы. Инструкции и кнопки вне таблицы сохраняются. Таблица с одними заголовками допустима после удаления последнего продукта; это также поддерживается обновлённым модулем `utils.food` в Obsidian.

## Штрихкоды

В редакторе справочника **▣** в верхней панели сразу открывает камеру, удержание — ручной ввод кода. Сканер также есть в форме новой еды при добавлении порции. CameraX и встроенная модель ML Kit распознают код на устройстве. Только штрихкод отправляется в Open Food Facts; фотографии и файлы дневника не загружаются. Вес и алиасы задаются пользователем, перед сохранением можно проверить данные по упаковке.

Приоритет — `energy-kcal_100g`. При отсутствии корректного значения `energy-kj_100g`/`energy_100g` переводятся из кДж делением на 4,184. Ошибочные данные товара `4620002683160` (1419 в поле ккал при близком значении кДж) обрабатываются проверкой согласованности: 339 ккал. Значения на порцию не смешиваются с данными на 100 г. Неизвестные поля не очищают введённые значения. Калорийность составного блюда остаётся расчётной.

Таймаут, обрыв и временные HTTP-ошибки повторяются один раз автоматически; read timeout 25 секунд, сетевой бюджет 55 секунд. 404/400/429 и ошибки сертификата не повторяются. Диагностика повторов — Android logcat, тег `ObsFitLookup`, без штрихкода и текста дневника.

Источники: [ML Kit](https://developers.google.com/ml-kit/vision/barcode-scanning/android), [Open Food Facts API](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v2/products/get-product-by-code/), [единицы энергии](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product_nutrition/), [Open Food Facts / ODbL](https://world.openfoodfacts.org/terms-of-use).

## Синхронизация и сохранение

Приложение использует [Android Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files); Syncthing настраивается отдельно. Текущий день перечитывается при возвращении к нему и по ↻; каждые 12 секунд на экране дня проверяются метаданные. Ближайшие даты загружаются при запуске и по ↻, следующие порции — при приближении к краю списка.

Перед записью проверяется исходный снимок файлов. Изменение через Obsidian/Syncthing останавливает сохранение вместо молчаливой перезаписи. Перед каждой записью сохраняется приватная резервная копия; хранятся последние 100 копий, экспорт доступен в настройках.

SAF не даёт транзакции на два документа и блокировки против Syncthing. Узкая гонка между последней проверкой и самой записью не исключена. Новый продукт сохраняется прежде порции; если справочник записался, а дневник — нет, приложение сообщает о частичном сохранении. Продукт можно выбрать из списка и добавить порцию повторно. Автоматическое восстановление поверх внешних изменений не выполняется.

## Архитектура

| Модуль | Назначение |
| --- | --- |
| `core` | Обычный Java-модуль без Android: Markdown, расчёты, поиск, формы, состояние, переходы, сеть и правила сохранения |
| `app` | Android lifecycle, SAF, камера, интерфейс и выполнение фоновых команд |

Основные части:

- `core/.../AppState`, `AppController` — типизированные экраны, переходы, возврат из редактора и маршрутизация результатов сканера.
- `core/.../PortionForm`, `CatalogForm` — значения полей, черновики и подготовка сохранения; ссылок на `View`/`EditText` нет.
- `core/.../VaultRepository` — сравнение снимков, резервные копии, сохранение и явная ошибка частичной записи. Зависит от интерфейсов `VaultStorage` и `BackupStore`.
- `core/.../VaultMarkdown`, `FoodSearch`, `RecipeIngredients`, `OffNutrition`, `HttpGet` — предметная логика и сеть.
- `app/.../MainActivity` — Android lifecycle, разрешения и выполнение команд. `SafVaultStorage` — адаптер документов Android.
- `app/.../ui/` — отдельные экраны дня, порции, списка продуктов, редактора и настроек; общие `Ui`, `UiDialogs`, `Swipes`.

Подробнее: [ARCHITECTURE.md](ARCHITECTURE.md). Предпочтения минималистичного интерфейса закреплены в [AGENTS.md](AGENTS.md).

```sh
./test-core.sh

```

Существующие 201 проверки сохранены в JUnit-регрессиях. Дополнительно проверяются возврат из редактора с сохранением веса и новым названием, сериализация черновиков, результат камеры до подключения папки, устаревший результат сканирования, пропущенные даты, жесты прокрутки, конфликты Syncthing, ошибка резервного копирования, неполная и частичная запись.

HTML-отчёт: `core/build/reports/tests/test/index.html`; JUnit XML: `core/build/test-results/test/`. Локальные HTTP-тесты используют только `127.0.0.1`, внешняя сеть тестам не нужна.

[GitHub Actions](.github/workflows/android.yml) запускает тесты и Android lint на push/PR и сохраняет отчёты. Версии actions закреплены SHA. CI проверяет сборку; установочные локальные APK сохраняют прежний debug-ключ телефона.

APK собирается только по отдельному запросу: в CI это ручной запуск с `build_apk: true`. При таком запуске дополнительно проверяются ELF LOAD-сегменты и ZIP-выравнивание 64-битных нативных библиотек на 16 КБ. CameraX обновлён до 1.4.2; ML Kit остаётся 17.3.0. Требования: [Android 16 KB page sizes](https://developer.android.com/guide/practices/page-sizes).

Проверено на Samsung Galaxy S23 Ultra (Android 16) через отдельный тестовый package и искусственное хранилище: выбор папки SAF, переход через пропущенный день и неактивные стрелки, ввод/правка/удаление калорий, отмена удаления, перенос свайпом в legacy «Перекусы» через «Перекус 4», составное блюдо с независимым весом порции, readonly расчётные поля, реальное распознавание штрихкода и заполнение из Open Food Facts, внешняя правка файла без refresh, обновление при возвращении из background, неизменность позиций элементов при фоновой проверке, индикатор ручного тяжёлого refresh, центрирование векторного refresh и минутный формат отсчёта. Реальный перенос Syncthing не подменялся записью в рабочие заметки; внешняя правка воспроизводилась в тестовой папке через ADB. Численный расход батареи не измерялся.
