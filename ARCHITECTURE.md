# Границы модулей ObsFit

## Направление зависимостей

`app` зависит от `core`. Обратной зависимости нет: Java-компилятор модуля `core` не получает Android SDK и не позволяет импортировать Android API.

`MainActivity` принимает события Android, выбирает SAF-папку, запускает камеру и фоновые операции. `ScreenRenderer` выбирает экран и действия панели из `AppState.Screen`. Экраны получают значения и интерфейсы команд `ScreenHost`; у них нет доступа к репозиторию.

## Состояние и формы

`AppState` хранит данные приложения, не `Activity`, `Context`, `View` или `Bundle`. Значения полей находятся в `PortionForm` и `CatalogForm`. Представления связывают редактируемый текст с этими значениями и отображают результат расчёта.

Для Android saved instance state используется отдельный `AppState.Saved` с сериализуемыми компактными черновиками. Снимки целых файлов в него не попадают. `CatalogForm.Draft` содержит SHA-256 исходного справочника; внешний конфликт не превращается в незаметное сохранение поверх новых данных.

Переход порция → редактор справочника сохраняет `PortionForm.Draft`. Возврат перечитывает дневник и каталог, сохраняет введённый вес, но берёт название, алиасы и калорийность из актуального справочника. Изменённая или исчезнувшая дневниковая строка не заменяется по старому индексу.

Штрихкод адресуется `ScanTarget`. Результат принимается только для ожидаемого кода и текущей формы. Смена формы сбрасывает ожидание. Результат, пришедший до окончания восстановления папки, дожидается восстановления формы. Сохранённый код позволяет повторить незавершённый lookup после пересоздания Activity.

## Файлы и резервные копии

`VaultStorage` работает с путями от корня хранилища и обычным текстом. `SafVaultStorage` в Android преобразует пути в document URI; в тестах используется `MemoryStorage`.

`VaultRepository` выполняет последовательность:

1. Проверяет исходные тексты затрагиваемых документов.
2. Сохраняет исходный текст через `BackupStore`.
3. Снова проверяет документ после резервного копирования.
4. Записывает новый текст и проверяет полученный результат.

Ошибка backup останавливает запись. Конфликт снимка имеет тип `StaleSnapshot`. Если новый продукт сохранился, а заметка — нет, выбрасывается `PartialSave`; успешно сохранённый продукт не удаляется автоматическим откатом.

SAF не предоставляет compare-and-swap или транзакции нескольких документов. Репозиторий не обещает полной атомарности с другим приложением. При ошибке сохраняются оригинал в backup и объяснение пользователю; автоматическая запись старой копии поверх возможных изменений Syncthing запрещена.

`FileBackups` сохраняет UTF-8, вызывает sync и ограничивает количество копий. Экспорт в системно выбранную папку остаётся в Android-адаптере.

## Общие компоненты интерфейса

`Ui` задаёт стили, поля, кнопки и каркас страницы. `UiDialogs` содержит меню и подтверждения. `Swipes` переводит Android MotionEvent в чистый `SwipeTracker`; различение тапа, горизонтального свайпа и вертикальной прокрутки проверяется без Android.

Ни один обработчик свайпа не пишет в файл напрямую. Он вызывает команду подтверждения удаления либо выбора раздела; сохранение начинается после пользовательского выбора.

## Как добавлять изменения

- Правило расчёта, преобразование Markdown, данные формы и переход помещайте в `core`, с JUnit-тестом наблюдаемого поведения.
- Виджеты, диалоги и подписи принадлежат `app/ui`; используйте общие компоненты и команды `ScreenHost`.
- Новый способ хранения реализует `VaultStorage`; новые проверки ошибок добавляются к `StorageTest` с подменным хранилищем.
- Проверки сети используют локальный сервер, а не доступность публичного Open Food Facts.
- Обычная проверка: `./gradlew :core:test :app:lintDebug`. APK собирается только по отдельному явному запросу пользователя.

## Обнаружение внешних изменений

`VaultStorage.Stamp` содержит nullable дату изменения и размер. `VaultRepository.load` снимает метаданные до и после чтения; кеш пригоден для пропуска чтения только при известной и неизменившейся тройке файлов. Ошибка чтения/разбора не заменяет последний успешный снимок и требует повторного чтения. `refresh` возвращает null при актуальном отображаемом снимке; если результат предыдущей проверки не попал на экран, кеш возвращает его повторно.

`SafVaultStorage` запрашивает только last_modified и size. `VaultObserver` подписывается на известные URI файлов и родительских списков, без I/O при регистрации. Уведомления — best effort, объединяются за 600 мс. Запасной опрос раз в 12 секунд работает только на открытом экране дня и в foreground. При onResume выполняется принудительное тихое чтение; ручной refresh также обновляет ближайшую порцию дат. При неизвестных метаданных чтение не пропускается. Совпадение размера и даты не является криптографической проверкой содержимого.

Фоновые проверки используют тот же последовательный I/O executor, не меняют busy и не показывают progress. Результат применяется только к прежнему выбранному дню, если пользователь не перешёл к форме или другой операции. Прокрутка берётся непосредственно перед обновлением экрана, раскрытые разделы сохраняются. Индикатор progress отделён от busy и включается при начальном подключении к хранилищу и явном нажатии ↻. Тесты `RefreshTest` используют управляемые метаданные, ошибки и изменения во время чтения, без Android и настоящих файлов пользователя.

## План приёмов пищи

`MealPlan` — чистая Java-модель восьми фиксированных окон и дневного ориентира из `VaultMarkdown.Day.dailyLimit` (fallback 2150 ккал). Основные приёмы и четыре перекуса берутся из отдельных разделов; только заметки распределяются приблизительно, без сохранения времени в документах. Равномерное перераспределение решается с нулевой нижней границей; целочисленное округление сохраняет сумму остатка. `MealPlanTest` проверяет границы окон, основной раздел, перекусы, заметки, недобор/перебор, недопущение двойного учёта и случайные варианты распределения.

`DayScreen` добавляет только подсказку для текущей даты. `Ui.clockHint` обновляет один TextView, MainActivity запускает минутный UI-таймер в onResume (следующий тик выравнивается по границе минуты) и снимает в onPause/onDestroy. Этот таймер не запускает load/refresh и не работает в фоне. Основной цикл проверки метаданных остаётся независимым.

## Состав новой еды из формы порции

`IngredientSection` — общий раскрывающийся интерфейс ингредиентов для `CatalogEditorScreen` и `PortionScreen`, с тем же `IngredientPicker`. `PortionForm.composition` использует чистую `CatalogForm` для списка ингредиентов и состояния раскрытия; значения названия/веса порции принадлежат `PortionForm`. `RecipeIngredients.nutrition` считает вес и калорийность независимо от наличия названия нового блюда.

При наличии состава `PortionForm` вычисляет вес по умолчанию и калорийность, а фактический вес порции отслеживает отдельно. Признак ручного изменения веса и состав входят в сериализуемый черновик. Недоступный ингредиент после восстановления даёт явную ошибку, а не пустой состав. Штрихкод может заполнить название, но не переопределяет калорийность рецепта. `VaultMarkdown.addFood` для рецептов использует тот же путь валидации и расчёта `putFood`, что редактор справочника; протокол backup/конфликтов и PartialSave сохраняется.

## Совместимость разделов перекусов

`VaultMarkdown.sectionName` — единственное соответствие старого имени `Перекусы` новому `Перекус 4`. Парсер, фильтр раздела, добавление, перемещение и восстановление черновиков используют каноническое имя. При записи четвёртого перекуса существующий новый заголовок имеет приоритет, затем используется старый, и лишь при отсутствии обоих создаётся новый. При смешанном документе все строки обоих заголовков относятся к четвёртому перекусу без повторного учёта.

`SECTIONS` задаёт порядок карточек, меню переноса и создания отсутствующих подразделов. Новые подразделы вставляются внутри «Питание» перед следующим существующим приёмом. `MealPlan` использует четыре отдельных слота по 225 ккал, включая Перекус 3 в 18:00–19:00, и также нормализует legacy-имя к последнему слоту. Чтение не мигрирует документы. `SnackSectionsTest` проверяет старые, новые, смешанные заметки и состояние предыдущей версии.

## Проверка нативной совместимости

`tools/check-apk-alignment.py` проверяет собранный APK: для arm64-v8a/x86_64 требует LOAD alignment ≥ 16 КБ, соответствие смещений ELF и 16-КБ смещение несжатых ZIP-entry. CI выполняет проверку после сборки и lint. Она выявляет прежнюю 4-КБ библиотеку CameraX 1.3.4 и проходит с CameraX 1.4.2. Иконка refresh использует `ic_refresh.xml` с центрированной icon-only группой MaterialButton, не шрифтовой символ.

## Вложенные рецепты

`RecipeIngredients` хранит выбранное блюдо и его вес одной записью, объединяя только повторные добавления того же блюда. `VaultMarkdown.catalog` сначала индексирует все названия и алиасы, затем рассчитывает зависимости обходом в глубину с кешированием. Порядок строк таблицы не влияет на результат; цикл отклоняется с цепочкой названий. При выборе ингредиента исключаются само редактируемое блюдо и все его транзитивные зависимые блюда. Переименование обновляет прямые ссылки, удаление используемого ингредиента блокируется. Валидатор Obsidian также должен поддерживать вложенные рецепты.

## Порционная навигация по датам

`VaultStorage.children` получает только непосредственных детей папки одним запросом; рекурсивного метода списка больше нет. `NoteIndex` ищет ближайшие даты очередью с приоритетом по временным границам папок года, квартала, месяца и ISO-недели, кешируя прочитанные списки. `DiaryLayout.weekFolder` вычисляет точный путь нужной недели в формате Moment ru; `window` сначала читает только её. При наличии дня или ближайшей прошедшей даты экран открывается сразу, а `extend` в фоне завершает поиск семи соседей с каждой стороны. Если неделя отсутствует или содержит только будущие даты, используется поиск ближайшего дня по диапазонам папок. Неизвестные имена папок наследуют границы родителя; attachments, assets и скрытые папки исключены. Файлы дней при индексации не читаются. Конфликты дат проверяются в загружаемой области, включая последнюю дату порции.

`window` возвращает накопленные даты из памяти. После показа дня `MainActivity` запускает `moreNotes` в фоне: `extend` добавляет ровно одну порцию из семи, только когда с соответствующей стороны осталось не больше двух загруженных дат. Повторный запрос в середине порции обхода не вызывает. Результат старого хранилища или фонового запроса во время основной операции не применяется. Список меню выбора даты фиксируется на время открытия. Ручной refresh получает даты из накопленного кеша и читает справочники и выбранный день. После показа экрана `refreshNearby` строит свежую ближайшую порцию, атомарно обновляет эту область кеша, сохраняя ранее посещённые даты вне неё. Ошибка провайдера оставляет прежний кеш. Стрелки обновляются через callback `Ui.updateNavigation`, без перерисовки заметки. Если выбранный файл удалён, перед загрузкой замены выполняется поиск ближайшей заметки.

`NoteIndexTest` проверяет предел запросов на 7000 днях, отсутствие чтения содержимого, предварительную загрузку и кеш, пропуски, границы ISO-недель/лет, пустое хранилище, новые/удалённые даты, конфликты, повтор после ошибки и сравнение со списком дат на случайных примерах.

## Норма калорий дня

`VaultMarkdown.dailyLimit` читает одно положительное поле `СуточнаяНормаКалорий::` в разделе «Спорт и диета», исключая код, комментарии, frontmatter и цитаты. Пустые, повреждённые, отсутствующие и неоднозначные значения дают 2150 ккал. Значение входит в `Day`, используется индикатором и `MealPlan`; схема восьми приёмов масштабируется пропорционально базовым 2600 ккал, перенос внутри дня остаётся равномерным. Приложение не вычисляет формулу похудения и не изменяет поле нормы при сохранении порций. В CI по push/PR выполняются тесты и lint; сборка APK и проверка 16 КБ включаются только через явный workflow_dispatch с build_apk.

## Прямое разрешение путей SAF

Для `com.android.externalstorage.documents` идентификатор документа вычисляется как `volume:path`, сохраняя выданное разрешение tree URI. Это соответствует [ExternalStorageProvider Android 16](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/packages/ExternalStorageProvider/src/com/android/externalstorage/ExternalStorageProvider.java). Для остальных провайдеров непрозрачные ID не конструируются: читаются и кешируются непосредственные дети каждого компонента пути. `children` возвращает пустой список для отсутствующей папки; ошибки доступа и недоступный корень остаются ошибками. Android DocumentsProvider возвращает null при FileNotFoundException, поэтому для отсутствующей вычисленной папки стандартного провайдера отдельно проверяется доступность выданного корня.

`DirectDiaryTest` проверяет первый запрос только к вычисленной неделе на 7000 днях, отсутствие обхода папок при перечитывании открытого дня, дозагрузку соседей, сохранение посещённых дат и откат после ошибки, произвольный суффикс имени заметки, границы календарного/недельного года и ID стандартного/непрозрачного провайдера.
