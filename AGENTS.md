# Интерфейс ObsFit

Пользователь выбрал минималистичный интерфейс. При дальнейших изменениях:

- Экономьте вертикальное пространство: не выделяйте строку для действия, которое помещается в существующую панель.
- Сокращайте переходы и число нажатий; предпочитайте прямые действия.
- Второстепенные подробности помещайте в раскрывающиеся секции.
- Не добавляйте ненужные подписи, экраны и подтверждения.
- Для компактных кнопок с символом сохраняйте понятное описание для доступности и удобную область нажатия.
- Горизонтальные группы создавайте через `Ui.row()`/`clickRow()`: они автоматически оставляют 8 dp между видимыми элементами. Не добавляйте к ним отдельные отступы между соседями.
- Поля создавайте через `Ui.field()` с общим outlined-стилем и симметричными внутренними отступами. Не задавайте filled-стиль поверх outlined-рамки.

# Структура и проверки

- Предметная логика, формы и переходы находятся в `core`; Android-зависимости там запрещены.
- Экраны и общие виджеты находятся в `app/.../ui`; данные формы не должны храниться в Android-полях.
- Работа с документами Android реализует `VaultStorage`; проверки сохранения и конфликтов относятся к `VaultRepository`.
- Для свайпов используйте общий `Swipes`/`SwipeTracker`, не копируйте обработчик на новый экран.
- Обычная проверка изменений: `./gradlew :core:test :app:lintDebug`. APK собирать только по отдельной явной команде пользователя, не при каждой доработке.
- Когда пользователь запросил APK, используйте `python3 tools/release.py`. Логика выпуска и хранения артефактов находится в скрипте; подробности в `README.md`.
- При изменении скриптов выпуска прогоняйте `python3 -B -m unittest discover -s tools -p 'test_*.py'`; эти тесты не собирают APK.

# Коммиты и GitHub

- После каждой завершённой доработки выполните подходящие проверки, создайте коммит и отправьте его в GitHub. Это относится также к документации, правилам, тестам и скриптам. Не накапливайте несвязанные доработки в одном коммите.
- Пишите содержательное название коммита и подробное описание: какую проблему решает изменение, какое поведение реализовано, что и как проверено, какие ограничения остались. Для многострочного сообщения используйте файл и `git commit -F`.
- Включайте в коммит только изменения текущей задачи; не захватывайте чужие незавершённые правки, APK, `dist/`, секреты и локальные настройки.
- После коммита выполняйте обычный `git push` без force. Если проверки или push не прошли, сообщайте об этом прямо; не представляйте такую доработку как полностью проверенную или опубликованную.
